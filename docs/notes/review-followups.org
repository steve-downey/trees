* TODO FingerTreeIntervalIndex — avoid intermediate vector in queries
:PROPERTIES:
:ID:       interval-index-query-fold
:AREA:     tree/interval-index
:PRIORITY: C
:END:

Current state (finger_tree_interval_index.hpp):
- =query_point(point)= and =query_overlap(start, end)= both:
  1. Split the tree at the monoid boundary (O(log n)) — correct and efficient.
  2. Call =flatten()= on the pruned right subtree — O(r) allocation where r is the
     candidate count after pruning.
  3. Apply =ranges::filter= over the vector — O(r).
- Complexity is already O(log n + r); the issue is the intermediate vector heap
  allocation when r is large.

Target:
- Replace =flatten()= + =ranges::filter= with a fold/traversal over the right
  subtree directly, accumulating only matching entries.
- This keeps O(log n + r) complexity but avoids materialising the full candidate
  set before filtering.
- Return type can remain =std::vector<Entry>= for call-site compatibility.

Acceptance checks:
- [ ] =query_point()= and =query_overlap()= no longer call =flatten()= internally.
- [ ] Existing interval index tests pass.
- [ ] 172/172 suite green.

Note: this is a lower-priority allocation improvement; the asymptotic class does
not change. Schedule after the RandomAccess and PriorityQueue items.

* TODO Reviewer Three: FixTree is not a true fixed-point combinator
:PROPERTIES:
:ID:       fix-tree-true-fixed-point
:AREA:     tree/fix-tree
:PRIORITY: C
:SOURCE:   reviewer-three.org § Recursion Schemes & Fix Trees
:END:

The reviewer correctly notes that =FixTree= in =smd/tree/fix_tree.hpp=
hardcodes a binary topology via =std::variant<Leaf, Node>= rather than being
a genuine fixed point over a higher-kinded functor. This means =cata= and =ana=
cannot be written generically over it; the fold in =FixTreeFoldableImpl= is
manual structural recursion.

For a talk whose thesis includes recursion schemes, this is worth addressing or
explicitly naming. Options:

1. Add a true =Fix<F>= template alongside the existing concrete tree, implement
   a generic =cata=, and use the concrete tree as an example instance.
2. Rename =FixTree= to something less misleading (e.g., =BinTree2=) and note
   explicitly in slides that it is a concrete tree, not the Fix combinator.
3. Keep as-is and call it out in the presentation as an intentional simplification.

The reviewer's suggested =Fix<F>= sketch (=template <template <class> class F>
struct Fix : F<Fix<F>>;=) is the right shape but inheriting from =F<Fix<F>>=
requires =F= to be a class template whose first parameter is its recursive
position — this is fine for trees but needs care for presentation clarity.

Acceptance checks:
- [ ] Decision made (extend / rename / note-in-slides) and recorded.
- [ ] If extended: generic =cata<F, A>(Algebra<F,A>, Fix<F>)= compiles and is
  tested.
